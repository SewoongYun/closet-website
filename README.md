# CLOSET 웹사이트 3차

2차 사이트에 태율이의 요청(2026-11-04 카톡)을 반영한 버전입니다. 방명록(구글 시트) 연결은 2차와 같은 주소를 그대로 씁니다.

- **클로젯 탭 → our archive(우리의 기록)**: 미니 매거진 5편(표지를 누르면 한 장씩 넘겨 보기), 반팔 디자인(누르면 사진 26장 앨범)
- **홈**: 미니 매거진 표지 미리보기 줄 추가
- **패션쇼 탭**: 액자를 "2025 Fashion show / 작년의 기록"으로 바꾸고, 누르면 2025 패션쇼 사진 화면(`#show-2025`)으로 이동
- **뷰어**: 휴대폰에서 좌우로 밀어서 넘기기
- 사진 목록은 `site/data.js` 한 곳에서 관리합니다.

### 작년 패션쇼 사진 넣는 법 (사진을 받은 뒤)
1. 사진을 `site/assets/show2025/` 폴더에 넣습니다. (긴 변 1500px 정도로 줄이면 빨리 열립니다)
2. `site/data.js` 맨 아래를 고칩니다.
   ```js
   show2025:{cover:'group.jpg',photos:['01.jpg','02.jpg','03.jpg']}
   ```
   `cover`는 패션쇼 탭 액자에 들어갈 단체 사진입니다. 비워 두면 지금처럼 CLOSET 글자와 "사진 모으는 중" 안내가 나옵니다.

# (2차 안내)

코덱스 1차 사이트의 디자인과 내용을 그대로 옮기고, **탭 구조**와 **방명록**을 더한 버전입니다.
빌드 과정이 없어서 `site` 폴더만 올리면 바로 배포됩니다.

```
2차_개발/
├─ site/             ← 이 폴더만 웹에 올립니다
│  ├─ index.html     내용(글, 탭 구성)
│  ├─ style.css      디자인
│  ├─ app.js         탭 전환, 매거진 뷰어, 방명록 동작
│  ├─ config.js      방명록 주소를 넣는 파일
│  └─ assets/        매거진 44쪽 이미지
├─ guestbook/
│  └─ Code.gs        방명록 서버 코드 (구글 Apps Script에 붙여 넣기, 웹에 올리지 않음)
└─ README.md
```

## 1. 웹에 배포하기

방명록을 연결하지 않아도 배포할 수 있습니다. 이 경우 방명록 탭에 "곧 열립니다" 안내가 나오고 나머지 탭은 정상 동작합니다.

| 방법 | 절차 | 어울리는 경우 |
|---|---|---|
| **Netlify Drop** (가장 빠름) | [app.netlify.com/drop](https://app.netlify.com/drop)에 로그인 → `site` 폴더를 끌어다 놓기 | 지금 바로 공개할 때 |
| **Cloudflare Pages** | 대시보드 → Workers & Pages → Create application → Drag and drop → `site` 폴더 | 주소를 오래 쓸 때 |
| **GitHub Pages** | 아래 4번 참고 | 수정 이력을 남기며 관리할 때 |
| **코덱스 호스팅** | 코덱스에게 `site` 내용을 기존 프로젝트의 `dist`로 재배포해 달라고 요청 | 지금 주소(chatgpt.site)를 유지할 때 |

- 로그인하지 않고 올린 사이트는 임시로 취급될 수 있으니 계정으로 로그인해서 올리세요.
- Cloudflare에서 끌어다 놓기로 만든 프로젝트는 **나중에 Git 연동으로 바꿀 수 없습니다.** Git을 쓸 계획이면 처음부터 4번 방법으로 하세요.
- 내용을 고친 뒤에는 같은 프로젝트에 `site` 폴더를 다시 올리면 됩니다. 주소는 그대로입니다.

## 2. 방명록 연결하기 (약 10분)

웹사이트는 글을 저장할 곳이 없으므로 저장소가 따로 필요합니다. 여기서는 **구글 시트를 저장소로, Apps Script를 중간 서버로** 씁니다.

```
방문자 → 사이트(방명록 탭) ⇄ Apps Script ⇄ 구글 시트 ← 선생님이 시트에서 공개/숨김 관리
```

1. 동아리에서 관리할 구글 계정으로 [새 구글 시트](https://sheets.new)를 만들고 이름을 `클로젯 방명록`으로 정합니다.
2. 시트 메뉴에서 **확장 프로그램 → Apps Script**를 엽니다.
3. 기본 코드를 모두 지우고 `guestbook/Code.gs` 내용을 붙여 넣은 뒤 저장합니다.
4. 오른쪽 위 **배포 → 새 배포** → 톱니바퀴에서 **웹 앱**을 선택합니다.
   - 실행 계정: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
5. **배포**를 누르고 권한을 승인합니다. "Google에서 확인하지 않은 앱" 경고가 나오면 **고급 → (프로젝트 이름)으로 이동**을 누릅니다. 본인이 만든 스크립트라서 나오는 안내입니다.
6. 표시된 **웹 앱 URL**(끝이 `/exec`)을 복사합니다. 브라우저 주소창에 넣었을 때 `{"ok":true,"notes":[]}`가 보이면 성공입니다.
7. `site/config.js`의 따옴표 안에 붙여 넣습니다.
   ```js
   window.CLOSET_CONFIG={guestbookUrl:'https://script.google.com/macros/s/.../exec'};
   ```
8. `site` 폴더를 다시 배포합니다. 방명록 탭에서 글을 남겨 시트에 줄이 추가되는지 확인합니다.

학교 Google Workspace 계정은 "모든 사용자"를 고를 수 없을 수 있습니다. 그때는 개인 Gmail 계정으로 만드세요.

## 3. 방명록 운영하기

- **글 공개:** 새 글은 시트에 쌓이고, **공개** 칸을 체크해야 사이트에 나타납니다. 학생 이름이 거론될 수 있는 공개 게시판이라 승인제를 기본으로 두었습니다.
- **글 숨기기:** 공개 칸의 체크를 풀거나 행을 삭제합니다. 사이트에는 최대 30초 뒤에 반영됩니다.
- **새 글 알림:** 시트의 **도구 → 알림 규칙**에서 변경 시 이메일 알림을 켭니다.
- **바로 공개로 바꾸기:** `Code.gs` 맨 위의 `REQUIRE_APPROVAL`을 `false`로 바꿉니다. 행사 당일처럼 글이 몰릴 때 유용합니다.
- **금칙어 추가:** `Code.gs`의 `BLOCKED_WORDS`에 단어를 넣습니다.
- `Code.gs`를 고친 뒤에는 **배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포**를 해야 반영됩니다. 이렇게 하면 URL은 바뀌지 않습니다.

스팸 방지 장치: 링크 금지, 금칙어 차단, 봇용 숨김 칸, 브라우저당 30초 간격, 사이트 전체 분당 20건 제한.
Apps Script는 방문자 IP를 알 수 없어서, 한 사람의 도배를 완전히 막지는 못합니다. 승인제를 유지하면 사이트에는 노출되지 않습니다.

## 4. Git으로 관리하기

이 폴더는 Git 저장소이고, main 브랜치에 올리면 `.github/workflows/deploy-pages.yml`이 `site` 폴더를 GitHub Pages로 자동 배포합니다.

처음 한 번만 설정합니다.

1. [github.com](https://github.com)에 가입하고 로그인합니다.
2. **New repository**로 빈 저장소를 만듭니다. 이름은 `closet-website`처럼 영문으로 짓고, **Public**을 선택합니다. README 등을 추가하는 옵션은 모두 끕니다.
3. 저장소 주소(`https://github.com/계정/closet-website.git`)를 이 폴더에 연결하고 올립니다. 처음 올릴 때 브라우저 로그인 창이 뜹니다.
   ```bash
   git remote add origin https://github.com/계정/closet-website.git
   git push -u origin main
   ```
4. 저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 바꿉니다.
5. **Actions** 탭에서 실패한 실행을 다시 실행하거나, 파일을 수정해 다시 올립니다. 끝나면 `https://계정.github.io/closet-website/`로 접속할 수 있습니다.

이후 수정할 때는 아래 세 줄이면 사이트가 자동으로 갱신됩니다.

```bash
git add .
git commit -m "수정 내용 요약"
git push
```

주의: 무료 GitHub Pages는 **공개 저장소**가 기본입니다. 올린 파일은 누구나 볼 수 있고, 한 번 올린 파일은 지워도 이력에 남습니다.
커밋 작성자 이메일도 공개되므로 이 저장소는 개인 이메일 대신 `closet@users.noreply.github.com`을 쓰도록 설정해 두었습니다.

## 5. 내용 수정하기

- 패션쇼 주제, 날짜, 장소: `site/index.html`에서 `공개 예정`, `추후 안내`를 찾아 바꿉니다.
- 시안 표시 제거: `WEB PREVIEW — 가안`과 `현재는 웹페이지 가안입니다` 문구를 지웁니다.
- 매거진 교체: `site/assets/page-01.jpg` ~ `page-44.jpg`를 같은 이름으로 바꿉니다. 쪽수가 달라지면 `app.js`의 `44`도 수정합니다.

## 방명록 저장소 비교

| 방식 | 비용 | 장점 | 단점 |
|---|---|---|---|
| **구글 시트 + Apps Script (채택)** | 무료 | 서버 없음, 시트에서 바로 관리 | 응답이 1~3초로 느린 편 |
| Supabase / Firebase | 무료 구간 있음 | 빠르고 확장성 좋음 | 보안 규칙 설정 필요, 관리 화면을 따로 만들어야 함 |
| Giscus / Disqus 등 외부 댓글 | 무료 구간 있음 | 붙이기 쉬움 | GitHub 또는 외부 계정 로그인 필요, 광고 가능성 |
